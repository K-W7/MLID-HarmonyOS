## 一、这次真正改掉了什么

### 1. 主页对齐官方日历
- 结构：`月标题 + 大日期（+ 星期·记录数）+ 周日开头 6×7 网格 + 三块回望`
- 每格带农历，节气/节日用赤陶色，有记录的日子用暖金小点
- 回望区三块统一成 `CardStack`：上叠、循环、官方 `onMove` 排序、空块自动隐藏
- 大日期副行从「农历+星期」改为「星期 · N 条记录」——避免与格子里的农历重复

### 2. 配色：ABC 融合（用户定的方向）
- **B 纸墨底座**：浅 `#F5F0EC` / 深 `#141311`，卡片 `#FBF7F1` / `#1E1D1B`
- **A 情绪色温**：`MoodTint.ets` + `TintProvider.ets`；有情绪用主情绪色，没情绪按时段（晨/午/暮/夜）
- **C 光**：顶部径向光，色温跟 A 走
- 强调色：暖金 `#C0914F`、赤陶 `#B4654A`、鼠尾草 `#8FA98C`
- 教训：**强调色当底色用** = 整页发黄（“屎黄”事件的根因）

### 3. 启动页 = 扉页（浅/深两套）
- 结构：页眉日期（农历用色温）→ 时 / 叙 依次浮现 → 朱砂「記」→ 页脚副题
- 2s 总时长；**只淡内容不淡背景**，否则中间露窗口黑底
- `peekThemeMode()` 同步读持久化主题，第一帧就正确
- 刻意不做：径向呼吸光、渐变字标、装饰细线（“三件套”= AI 味）

### 4. 动效（全部官方能力）
| 场景 | 实现 |
|---|---|
| 保存落笔 | 新卡 460ms 弹入 + 草稿卡下沉 280/300ms |
| 日期选中 | 90ms 下压 0.94 + 220ms 回弹 |
| 删除 | 180ms 压扁淡出后落库，列表补位 |
| 图片预览 | `geometryTransition` 缩略图 ↔ 全屏 |
| 空态 ↔ 列表 | 220ms 淡入 |
| 切月 | 大日期先淡出、落定再淡入 |
| 减弱动画 | 全部压到 120ms，呼吸停止 |

### 5. 多设备
- `deviceTypes`：phone / tablet / 2in1
- 宽屏内容限宽 760 居中（`sidePadding()`），手机路径未变
- 未做：平板双栏、PC 侧栏（无设备验证，风险大于收益）

## 二、踩过的坑（可复用的经验）

### 环境类
1. **`uitest` 合成滑动会被 List×Swiper 嵌套手势吞掉**——切月、卡片划动、左滑操作都无法自动验证，只能手测。
2. **`uitest` 点击可能双击**——一次点击会同时确认弹窗，破坏性操作（清空/重置）绝不能靠盲坐标测试。
3. **`Area.width` 是带单位的字符串**，`Number()` 得 NaN，必须 `parseFloat(\`${width}\`)`。
4. **`@Builder` 里读 `@Local` 不会触发重建**——需要包成 `@ComponentV2` 组件，用 `@Param` 传值（`RandomSection`/`CardStack` 就是这么来的）。
5. **`NavDestination` 的 API 名是 `onDisAppear`**（大写 A），不是 `onDisappear`。
6. **`Alignment.CenterStart` 不存在**，用 `Alignment.Start`。

### 主题类
7. **只读 `context.config.colorMode` 会在切换瞬间滞后**——必须读应用设置，否则“卡片变白、底色还黑”。
8. **主题切换不会自动重建组件**——需要注册 `environment` 回调，在回调里刷新缓存的 `tint`；颜色用 `animateTo` 过渡 1.2s。
9. **状态栏图标色要应用级设置**（`setWindowSystemBarProperties`），页面内改不到。
10. **启动窗口颜色取资源**，系统深色时会先闪黑——`EntryAbility` 里按持久化主题预置窗口底色可以压掉。

### 交互类
11. **输入框恢复焦点会带起键盘和胶囊**——需要“用户手指点过才允许展开”的门控。
12. **键盘不改变列表可视高度**，最后一张卡会被输入岛压住——展开时主动 `scrollEdge(Bottom)` + 底部预留。
13. **`onMove` 只对 List/Grid 生效**，整页做成一个 List 才能拖拽排序；下标要映射回可见区块 key。

### 产品类
14. **功能做不出来就砍，别留半成品**：提醒依赖系统提醒服务，三种类型都返回 `1700002`，砍掉反而让“零权限”成立。
15. **设置页不要为填满而加条目**：清理缓存、语言切换、数据概览都被用户当场否掉。
16. **“AI 味”的三个典型特征**：径向呼吸光、渐变字标、装饰细线。去掉之后用留白和符号（朱砂印）建立识别度。

## 三、过程教训（比技术更重要）

1. **先确认再修**：用户明确要求过；这次误判过一次“数据被清空”（其实是用户自己删的），浪费了口舌。
2. **不要盲点坐标做破坏性操作**；也不要在我改过布局后沿用旧坐标。
3. **改动先编译再汇报**，装机后**重启应用**再验证（否则看到的是旧进程）。
4. **验证不了的不要说“应该可以”**：那次“逐张入场动画”实际没实现，用户一眼看穿。
5. **文档会被渲染覆盖**：`当前框架.md` 是从 `flow.json` 渲染的，改文档必须同时改 JSON，否则下次渲染全丢。
